How It Works

Every uploaded SVG passes through a six-step preprocessing engine before a single frame is animated.

01

Validation & Sanitization

The file's MIME type is verified, then the raw text is passed through DOMPurify with the svg profile, stripping any embedded scripts or foreign objects that could pose a security risk before parsing begins.

02

Resolve <use> References

SVGs commonly re-use geometry via <use href="#id">. The animation engine cannot reach inside the shadow DOM of <use> elements, so every reference is resolved: the target is deep-cloned, x/y offsets are baked in as a transform, and the <use> tag is replaced with real geometry.

03

Shape → Path Conversion

All primitive shapes (<circle>, <ellipse>, <rect>, <line>, <polyline>, <polygon>) are converted to equivalent <path> elements with mathematically precise d attributes. Rounded rectangle corners use arc commands. All original attributes are preserved.

04

Transform Flattening

Nested transform attributes distort stroke-dash animation math. The engine traverses the ancestor chain for every path, computes the accumulated transformation matrix, bakes it into the path coordinates using full SVG path command parsing, and removes all transform attributes.

05

Stroke & Fill Isolation

Self-draw animation requires a stroke. Paths with only a fill have their fill color moved to stroke, and fill is set to none with the original stored in data-original-fill. Stroke width is set automatically to 0.5% of the viewBox diagonal — correct on both 24px icons and 2000px illustrations.

06

ViewBox Normalization

If the SVG lacks a viewBox, one is synthesized from width/height attributes. Absolute dimensions are removed and replaced with width:100%; height:100% so the preview scales fluidly without distortion.
